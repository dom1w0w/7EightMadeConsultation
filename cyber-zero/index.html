01

Linux — the ground everything stands on

~2–3 evenings

End state: you can move through a Linux box, find anything on it, read its logs, and control who can touch what — without a mouse.

Every server, every target, every lab runs Linux. Windows is where you sit; Linux is where the work happens. Four ideas carry the whole module:

  • Everything is a file. Configs, devices, logs — all files. If you can navigate and read files, you can read the machine.
  • The filesystem has a map. /etc = configs, /var/log = logs, /home = users, /tmp = scratch space (attackers love it), /usr/bin = programs.
  • Permissions are three numbers. Read=4, Write=2, Execute=1, for Owner/Group/Others. chmod 755 = owner does everything, everyone else reads and runs. A file at 777 is a door left open.
  • Text pipelines are the superpower. Small tools chained with | — grep filters, sort orders, uniq -c counts, cut/awk pull columns. This is how an analyst turns a million log lines into one answer.

02

Networking — how machines actually talk

~2–3 evenings

End state: given any connection, you can say what it is, where it's going, and whether it should exist.

  • IP + port = address + apartment number. The IP finds the machine; the port finds the service on it. 93.184.216.34:443 = that building, the HTTPS door.
  • Ports worth memorizing: 22 SSH · 80 HTTP · 443 HTTPS · 53 DNS · 21 FTP · 25 SMTP · 3389 RDP · 445 SMB. An open port you don't recognize is a question that needs an answer.
  • TCP vs UDP. TCP = signed-for delivery: handshake, order guaranteed, resends. UDP = postcard: fast, no guarantees. DNS rides UDP; the web rides TCP.
  • DNS is the phone book — and a weapon. It turns names into IPs. Whoever controls DNS controls where "the bank" points. Always ask: who answered this lookup?
  • The handshake: SYN → SYN-ACK → ACK. Three packets and a connection exists. A port scan is just knocking with SYNs and listening for who answers.

See it: a live capture (Wireshark-style)

Wireshark is the microscope — it records every packet so you can read conversations off the wire. Filter the capture the way an analyst does:

03

Web fundamentals — where the attacks live

~3 evenings

End state: you can read an HTTP conversation like a transcript and name where it can be bent.

  • HTTP is a request and an answer. Method + path + headers go out; a status code + headers + body come back. 200 ok · 301 moved · 403 forbidden · 404 not here · 500 server broke.
  • Methods: GET asks, POST sends, PUT replaces, DELETE removes. The method is a claim — the server decides whether to honor it.
  • HTTP forgets you. It's stateless, so sites bolt memory on: cookies. Your session cookie is your login — steal the cookie, become the user. That's why session handling is a top attack class.
  • The classic breaks (know the shapes, the labs teach the hands): SQL injection — input that becomes a database command · XSS — input that becomes someone else's script · IDOR — changing an ID in the URL to see someone else's data · broken access control — asking for the admin page directly. One root cause: the server trusted what the browser sent.

Fire a request — watch the session work

Pick a request and send it. Try /account with and without the cookie — then change the id.

Your own lab — break things that are yours

one weekend to stand up

End state: a deliberately vulnerable web app running on your machine, and the proxy that lets you watch — and bend — every request it makes.

Guided labs end. A home lab doesn't. Two builds:

Build 1 — OWASP Juice Shop (the target)

Juice Shop is a modern web store riddled with real vulnerabilities on purpose — 100+ challenges, scored like a game. Docker runs it in a sealed container: up in one command, deleted in one command, nothing touches your real system.

Build 2 — Burp Suite (the intercepting proxy)

Burp sits between your browser and the target. Every request passes through your hands — read it, change it, replay it. This is the tool Module 3 was about.

Your browser→ BURP — intercept, edit, replay→ Juice Shop :3000
  1. Install Burp Suite Community (free) from PortSwigger.
  2. Use Burp's built-in browser — zero proxy configuration, it just works.
  3. Browse Juice Shop normally. Watch the HTTP history fill: every request you made, recorded.
  4. Turn Intercept on, log in, and hold the login request hostage. Read every field. Change one. Forward it.
  5. Send a request to Repeater and fire it ten times with small changes. That loop — observe, bend, replay — is the entire offensive web skill.
The rule of the lab: everything in this module happens on machines and apps you own, on your own network. That line — yours, or explicitly permitted — is the whole legal difference between a security professional and a defendant. It never moves.

06

Projects — automate it, in Bash then Python

the proof module

End state: two working tools you built yourself that do a real analyst's job — and the habit that matters: when you've done it twice by hand, script it.

Same job both times: find the brute-force attack hiding in an SSH auth log. First with a Bash pipeline (the Module 1 superpower), then as a Python program (the automation you'll reuse forever). The Range's /var/log/auth.log is the same log both projects chew on.

Project A — Bash: the one-line investigation

An analyst's question: which IP is hammering this server? The pipeline, piece by piece:

grep "Failed password" /var/log/auth.log # keep only the failures
  | awk '{print $11}'                # column 11 = the source IP
  | sort                            # group identical IPs together
  | uniq -c                         # count each group
  | sort -nr                        # biggest count first

Your move: go to The Range and run that exact pipeline. Mission 4 completes when the terminal sees the right answer come out of your hands — not a button press.

Project B — Python: the same job, as a tool

Bash is a scalpel; Python is the workshop. This program reads the log, counts failures per IP, and prints a verdict. Read it top to bottom — every line is annotated — then run the simulation and watch it think.

import re
from collections import Counter

LOG = "/var/log/auth.log"
THRESHOLD = 5                      # 5+ failures = brute force, not a typo

pattern = re.compile(
    r"Failed password for (?:invalid user )?\w+ from (\d+\.\d+\.\d+\.\d+)")

counts = Counter()
with open(LOG) as f:
    for line in f:
        m = pattern.search(line)
        if m:
            counts[m.group(1)] += 1   # tally one hit for that IP

for ip, hits in counts.most_common():
    verdict = "BRUTE FORCE" if hits >= THRESHOLD else "watch"
    print(f"{ip:16} {hits:3} failed logins  {verdict}")
